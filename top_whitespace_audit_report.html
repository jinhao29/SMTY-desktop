Android 页面顶部空白全量排查报告

仓库：android_app（com.shangmentiyu.sportscoach） · 排查时间：2026-09-02 · 范围：全部 Screen / Tab（24 Screen + 10 Tab + 外壳与通用组件）

一、根因：双重状态栏避让（系统性）

证据链：

  • MainActivity 调用 enableEdgeToEdge()，状态栏 inset 生效；
  • 外层 SportsApp.kt 的 Scaffold：topBar 为桌面连接横幅（隐藏时高度 = 0），M3 Scaffold 在 topBar 无高度时按默认 contentWindowInsets = systemBars 将状态栏高度计入 innerPadding → NavHost 内所有页面已经从状态栏下方开始；
  • 内层各页面自行使用 M3 TopAppBar，其默认 windowInsets = TopAppBarDefaults.windowInsets（状态栏），又在顶栏内部避让了一次状态栏 → 顶栏上方多出约 24–48dp 重复空白。

代码库自身注释可交叉印证：HomeScreen.kt:101「contentWindowInsets 设为 0，避免 Scaffold 默认 inset 叠加」；CoachManageScreen.kt:106「外层 SportsApp Scaffold 已消费状态栏 inset，此处归零避免双重留白」——即 coach 模块的已修复项用的就是此结论。

// ✅ 已修复参照（CoachManageScreen.kt:107） TopAppBar( title = { Text("教练管理", fontWeight = FontWeight.SemiBold) }, // 外层 SportsApp Scaffold 已消费状态栏 inset，此处归零避免双重留白 windowInsets = WindowInsets(0, 0, 0, 0), colors = glassTopAppBarColors() )

三、统一修复方案（最小 diff，沿用 CoachManageScreen 已验证写法）

方案 A（推荐，19 处一行修改）：全部问题 TopAppBar 统一增加 windowInsets = WindowInsets(0, 0, 0, 0)；SportStandardDetailScreen 则删除 .statusBarsPadding()。

// 每处仅增一行（import androidx.compose.foundation.layout.WindowInsets 已在多数文件存在，缺则补） TopAppBar( title = { Text("上课签到") }, windowInsets = WindowInsets(0, 0, 0, 0), // ← 新增：外层已消费状态栏 inset ... ) // SportStandardDetailScreen.kt:81 反向修改（删一行） Row( modifier = Modifier .fillMaxWidth() // .statusBarsPadding() ← 删除：外层 inset 已由 SportsApp 统一避让 .padding(horizontal = 4.dp), )

方案 B（可选进阶，二期）：在 ui/theme/GlassCard.kt 旁抽一个共享 AppTopBar()（内置 windowInsets=0 + glassTopAppBarColors()），新页面一律复用，杜绝再犯。一期先用方案 A 收敛存量。

不推荐：反转约定（外层 contentWindowInsets=0、内层默认避让）——虽只改 5 处，但会推翻 HomeScreen/SettingsScreen 已固化的「胶囊紧贴状态栏」布局，回归风险高。
